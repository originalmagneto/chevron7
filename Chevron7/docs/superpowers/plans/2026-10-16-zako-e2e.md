# ZaKo E→E Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An advocate converts a client's signed PDF or single-PDF ASiC-E into a new electronic document with the E→E clause, signs both with the mandate certificate, registers it and sends the E→E record to EZZK (Demo and Testovacia evidencia; production only with a qualified validation output attached).

**Architecture:** The Java engine gets one new machine v2 operation (`EVIDENCE`) that validates a file against the trusted lists and returns everything the clause and record need plus the ETSI report and PDF/A facts, and one new command-line entry (`PdfaFromSigned`) that flattens and converts a PDF that is not acceptable. Swift decodes the evidence into a form-version-independent `ElectronicOriginal`, renders the official E→E clause 1.3 and record 1.0, and the ZaKo flow gains a direction choice and a verification step; signing, register and EZZK submission reuse the P→E path.

**Tech Stack:** Swift 6 / SwiftUI / XCTest (`swift test`), Java 25 / DSS 6.4 (`dss-pdfa` for veraPDF) / PDFBox 3 / JUnit (Maven, `engine/`), `xmllint`.

**Spec:** `Chevron7/docs/superpowers/specs/2026-10-16-zako-e2e-design.md` (approved 2026-10-16, revision 3).

## Review Focus

- A client PDF whose PAdES signature covers the file but which DSS reports with a later annotation or form-fill revision: the verification step must refuse it with the changed revision named, never certify it (Task 2 test `pdfChangedAfterLastSignatureIsReported`, Task 7 test `refusesChangesAfterLastSignature`).
- A signed PDF/A-3 with an attachment: must be converted, not kept (Task 2 test `pdfaWithAttachmentIsNotKeepable`, Task 7 test `pdfa3WithAttachmentIsConverted`).
- A trusted list that did not load during verification: blocks with "Skúste overenie znova", never "nie je možné zistiť" in a record (Task 7 test `unloadedTrustedListBlocks`).
- Evidence number allocated, then verification redone with a different result: the authorization must use the latest verification, never a stale one (Task 11 test `reverificationReplacesEvidenceBeforeAuthorization`).
- A qualified report for another document imported in production: refused (Task 9 test `reportForAnotherDocumentIsRefused`).
