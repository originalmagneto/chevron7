# CLI and MCP Implementation Plan

> **For agentic workers:** Execute the approved design with independently owned components and a final whole-branch review. Track completed checks below.

**Goal:** Ship a native CLI and stdio MCP adapter using the app's confirmed signing and read-only services.
**Architecture:** Shared Chevron7Integration contract/client and safe file/job primitives, a separate authenticated app XPC interface, and one bundled executable. The app owns providers and all signing UI.
**Tech Stack:** Swift 6, Foundation XPC, CryptoKit, official Swift MCP SDK, XCTest.
**Spec:** ../specs/2026-11-07-cli-mcp-design.md (approved by the owner 2026-11-07).

## Global Constraints
- No PIN through CLI/MCP, no HTTP listener, no conversion or EZZK writes.
- Input and output isolation, explicit register/EZZK grants, one active signature, no automatic signing retry.
- Encoded requests <=32 MiB, outputs <=64 MiB, retained data <=256 MiB, <=64 jobs, terminal TTL 30 minutes.
- Tests use temporary roots, memory defaults and fake credentials; never touch the real register.
- Keep root AGENTS.md and CLAUDE.md mirrored. Work from main b458d059 in codex/cli-mcp.

## Review Focus
- A client disappearing after a signature is made must not trigger another signature.
- A path replaced with a symlink must not escape a client's roots.
- An integration cancellation must not cancel Safari or another UI validation.
- A returned signature with incomplete validation must remain distinguishable from a signing failure.
- An old app paired with a new helper must fail explicitly rather than hang.
